# SQL Aggregation — Foundation Notes

## Why do we need this?

Data engineers convert millions of event rows into metrics such as revenue, daily active customers, success rate, and average order value. Aggregation combines many rows into a **summary**.

## 1. Input data

| id | status | amount |
|---:|---|---:|
| 1 | paid | 100 |
| 2 | paid | 200 |
| 3 | failed | 50 |
| 4 | paid | NULL |

## 2. Understand what each function counts

```sql
SELECT
  COUNT(*) AS rows_seen,
  COUNT(amount) AS known_amounts,
  SUM(amount) AS amount_total,
  AVG(1.0 * amount) AS mean_known_amount
FROM Transactions;
```

| rows_seen | known_amounts | amount_total | mean_known_amount |
|---:|---:|---:|---:|
| 4 | 3 | 350 | 116.67 (approx.) |

```text
COUNT(*)          4 rows
COUNT(amount)     3 non-NULL values
SUM(amount)       100 + 200 + 50 = 350
AVG(amount)       350 / 3 ≈ 116.67
```

**Why:** SQL aggregates such as `SUM`, `AVG` and `COUNT(column)` ignore `NULL` inputs. `COUNT(*)` counts rows regardless of NULL. If no non-NULL amounts exist, `SUM(amount)` is NULL, not zero.

## 3. Conditional aggregation

```sql
SELECT
  SUM(CASE WHEN status='paid' THEN 1 ELSE 0 END) AS paid_count,
  SUM(CASE WHEN status='paid' THEN amount ELSE 0 END) AS paid_amount
FROM Transactions;
```

| paid_count | paid_amount |
|---:|---:|
| 3 | 300 |

Even with unknown amount for a paid row, it still contributes **one** to the count; its NULL amount does not contribute money.

## 4. Ratios and safe division

```sql
SELECT
  100.0 * SUM(CASE WHEN status='paid' THEN 1 ELSE 0 END)
  / NULLIF(COUNT(*), 0) AS paid_pct
FROM Transactions;
```

**Result:** 75.0. Multiplying by `100.0` avoids integer truncation in SQLite. `NULLIF(x,0)` makes a zero denominator NULL rather than dividing by zero.

## 5. Join fan-out warning

If one order has three order-item rows, joining Orders to Items produces **three joined rows** for that order. Summing the **order-level** total *after* that join counts it three times. Aggregate items to order grain first, or compute the desired metric from a grain-appropriate table.

**JS analogy:** Think `reduce()` over an array, but identify the units being reduced and whether the array was duplicated by a join.

## Quick revision

- `COUNT(*)` ≠ `COUNT(column)` when NULL exists.
- Decide whether `NULL` means unknown before replacing it with zero.
- Weighted average = `SUM(value * weight) / SUM(weight)`, **not** average of group averages.
- Separate original row grain, business metric grain, and grouping key.
