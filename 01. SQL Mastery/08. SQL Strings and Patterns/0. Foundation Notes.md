# SQL Strings and Pattern Matching — Foundation Notes

## Why do we need this?

Incoming API and CSV data is messy: an email may be `"  MEERA@EXAMPLE.COM "`, names may contain spaces, and postal codes should not lose leading zeros. **Cleaning text is a data-quality task**, not merely formatting.

## 1. Clean one record

```text
"  MEERA@EXAMPLE.COM  "
       ↓ TRIM
"MEERA@EXAMPLE.COM"
       ↓ LOWER
"meera@example.com"
```

```sql
SELECT LOWER(TRIM('  MEERA@EXAMPLE.COM  ')) AS cleaned_email;
```

| cleaned_email |
|---|
| meera@example.com |

This transforms only the selected output; it does **not** update the stored data.

## 2. Useful text operations

| Question | SQLite | SQL Server |
|---|---|---|
| Remove outer whitespace | `TRIM(text)` | `TRIM(text)` |
| Lowercase | `LOWER(text)` | `LOWER(text)` |
| Length | `LENGTH(text)` | `LEN(text)` (trailing spaces differ) |
| Extract substring | `SUBSTR(text,1,3)` | `SUBSTRING(text,1,3)` |
| Concatenate | `a || b` | `CONCAT(a,b)` |
| Replace text | `REPLACE(text,'x','y')` | `REPLACE(text,'x','y')` |

## 3. LIKE visual

For text `'meera@example.com'`:

- `'m%'` matches any string starting with m.
- `'%@example.com'` matches that email domain suffix.
- `'_e%'` matches exactly **one character** before e, then anything.

```sql
SELECT email
FROM Customers
WHERE LOWER(TRIM(email)) LIKE '%@example.com';
```

**Caution:** This is a domain filter, **not full email validation**. SQL `LIKE` does not provide regular-expression validation or guarantee a valid mailbox.

## 4. NULL, collation and regex

- `LOWER(NULL)` and `TRIM(NULL)` normally remain NULL.
- SQLite `LIKE` case behavior depends on configuration/Unicode; SQL Server collation controls case sensitivity.
- SQLite's `REGEXP` operator needs a registered user-defined function; it is not built-in in stock SQLite. Do not paste MySQL regex syntax into SQLite without checking.
- Keep normalized values separate from raw inputs when traceability is required.

**JS analogy:** `email.trim().toLowerCase()` is conceptually `LOWER(TRIM(email))`. SQL returns NULL for NULL input rather than throwing a JS TypeError.

## Revision

First decide whether the task is **cleaning**, **extracting**, **matching**, or **filtering**. Use the right operation. Avoid broad regex rules that silently reject valid records.
