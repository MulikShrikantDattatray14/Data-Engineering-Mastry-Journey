# SQL Gaps and Islands — Foundation Notes

## Why do we need this concept?

Suppose users log in on several days. A Data Engineer needs to find **consecutive-day streaks**: who logged in for 3 straight days? Simple `GROUP BY user_id` cannot distinguish separate streaks. **Gaps and Islands** is the pattern for grouping contiguous runs of dates or numbers.

## 1. Small example

| user_id | login_date |
|---:|---|
| 1 | 2025-01-01 |
| 1 | 2025-01-02 |
| 1 | 2025-01-03 |
| 1 | 2025-01-05 |
| 1 | 2025-01-06 |
| 2 | 2025-01-01 |
| 2 | 2025-01-03 |

Expected streaks: user 1 has **Jan 1–3 (3 days)** and **Jan 5–6 (2 days)**; user 2 has two separate one-day streaks.

## 2. Visual: why row numbers help

```text
User 1 login day   row_number   day minus row_number
Jan 01             1            Dec 31   ┐
Jan 02             2            Dec 31   ├ same island
Jan 03             3            Dec 31   ┘
Jan 05             4            Jan 01   ┐ new island
Jan 06             5            Jan 01   ┘
```

**Core trick:** Consecutive dates increase by one day at the same rate as `ROW_NUMBER()`. Subtracting the row number leaves a constant **island key** within a streak.

## 3. SQLite query — progressive CTEs

```sql
WITH unique_days AS (
  SELECT DISTINCT user_id, login_date
  FROM Logins
),
numbered AS (
  SELECT user_id, login_date,
         ROW_NUMBER() OVER (
           PARTITION BY user_id ORDER BY login_date
         ) AS rn
  FROM unique_days
),
islands AS (
  SELECT user_id, login_date,
         date(login_date, '-' || rn || ' day') AS island_key
  FROM numbered
)
SELECT user_id, MIN(login_date) AS start_date,
       MAX(login_date) AS end_date, COUNT(*) AS streak_days
FROM islands
GROUP BY user_id, island_key
ORDER BY user_id, start_date;
```

**Final output**

| user_id | start_date | end_date | streak_days |
|---:|---|---|---:|
| 1 | 2025-01-01 | 2025-01-03 | 3 |
| 1 | 2025-01-05 | 2025-01-06 | 2 |
| 2 | 2025-01-01 | 2025-01-01 | 1 |
| 2 | 2025-01-03 | 2025-01-03 | 1 |

**Why `DISTINCT` first?** Duplicate login events on the same day must not count as extra days. `PARTITION BY user_id` prevents combining different people's streaks.

## 4. SQL Server version of the island key

Use `DATEADD(day, -CAST(rn AS int), CAST(login_date AS date))` in place of the SQLite `date(...)` expression. The windowing/grouping idea is the same; this is a **dialect conversion, not an independently executed SQL Server test**.

## 5. Problems to watch for

- Multiple events on the same calendar day: deduplicate first.
- Time-zone cutoffs: define which time zone determines a day.
- Missing days break a streak; repeated days do not extend one.
- For consecutive **numbers** instead of dates, `value - ROW_NUMBER()` can serve as the island key.
- For irregular times or tolerance thresholds, this simple trick is not enough; compare gaps with `LAG()` and cumulative grouping.

**JS developer analogy:** Sort dates, keep a previous-date variable and start a new group when the difference exceeds one day. SQL solves the same idea declaratively with windows and grouped keys.
