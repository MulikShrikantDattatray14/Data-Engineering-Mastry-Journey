## Q086 — original order-header versus line-value reconciliation

- **Source task:** emit **11 distinct statuses, including zero-count statuses**, applying listed rules top to bottom and **return statuses in that source-specified order**. The question's sample places *Lines with NULL OrderID* first, *Exact match* fifth.
- **Previously established task-contract mismatch, now reconfirmed on unchanged PostgreSQL SQL:** supplier key's `statuses(sort_order, recon_status)` VALUES assigns `Exact match` order **1**, *Lines with NULL OrderID* order **11**. Even for the **original one-order example** (header 20, one two-unit product at 10, Card), native query returns the correct *Exact match* **values** (1 order, 20/20, difference 0, Card), but **puts that row first** rather than fifth and returns all eleven rows in reversed priority-group order. Prior SQLite source reviewer had identified this discrepancy; **do not double-count as a new unique discovery**.
- **Newly reproduced conditional one-cent precision discrepancy:** source wording says *header equals line value to the cent*. Original key instead uses `ABS(header - line_value) <= 0.01` for *Exact match*. Native PostgreSQL numeric test with **header 19.99, line 20.00** produces *Exact match* with absolute difference **0.01**, although values rounded to cents differ. This is a source-policy discrepancy, not an authenticated provider grading error.
- **Other replayed boundaries:** source example with eleven status labels and ten zero-count rows; each of 5/10/12/15 percent discounts; unmatched line `OrderID=999` counts one order and 20 line value, whereas NULL-order-ID lines count **zero** order keys while reporting 20 line value; missing-header, zero and negative-header, shortfall, above-lines and multiple-payment examples. Missing `Products` reference converts unknown catalogue-price line value into **0** using `COALESCE`, a data-quality caveat requiring actual source-population checks. Original Commerce v2 CSV presence of such unmapped rows is **not inferred** from this fixture.
- **Evidence status:** supplier statement **inspected**, **synthetic native PostgreSQL test passed**. Source output-row-order and cent-equivalence contracts **not satisfied by original supplier key** on reproducible fixtures; provider answer/key authentication and actual CSV output remain unverified.
