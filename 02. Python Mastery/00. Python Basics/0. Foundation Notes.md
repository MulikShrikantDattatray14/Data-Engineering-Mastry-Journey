# Python Basics — Foundation Notes

**Main idea:** Python stores values in variables and uses their types to decide what operations are valid. This is the quick-revision version of the [original lessons on programs, variables, numbers, strings and input/output](../../99.%20Reference%20Materials/Original%20Mastery%20Snapshot/2.%20Python%20Mastry/1.%20Python%20from%20Zero/README.md), not a separate PDF completion record.

## 1. Your first program

```python
print("Hello, Python")  # Hello, Python
```

`print()` displays a value. Python uses indentation for blocks rather than JavaScript's braces.

| JavaScript | Python |
|---|---|
| `console.log(x)` | `print(x)` |
| `let age = 24` | `age = 24` |
| `null` | `None` |
| `true / false` | `True / False` |

## 2. Variables and types

A variable is a name referring to a value. Python is dynamically typed: you do not declare `let`, `const` or a fixed type.

```python
amount = 2500           # int
status = "SUCCESS"      # str
rate = 0.18             # float
is_paid = True          # bool
amount = "2500"         # now str
print(type(amount))     # <class 'str'>
```

**Why:** CSV fields may look numeric but arrive as strings. Check or convert them before calculations.

## 3. Type conversion

```python
amount_text = "2500"
amount = int(amount_text)
print(amount + 500)       # 3000
print(str(amount) + "INR") # 2500INR
print(float("2.5"))       # 2.5
```

- `int()` converts a compatible value to an integer.
- `float()` converts to a floating-point number.
- `str()` converts to a string.
- Invalid conversions such as `int("hello")` raise `ValueError`.

## 4. Strings

Strings store text. Indexing begins at 0; slices stop **before** the end position.

```python
city = "Pune"
print(city[0])       # P
print(city[-1])      # e
print(city[:2])      # Pu
print(city.lower())  # pune
print(city.strip())  # Pune
```

**JavaScript link:** `city.toLowerCase()` ≈ `city.lower()`; `city.trim()` ≈ `city.strip()`.

### Why cleaning strings matters in Data Engineering

External CSVs and APIs may contain values like `"  PAID "` and `"paid"`. They mean the same business status, but an exact comparison sees different strings until we normalize them.

```python
raw_status = "  PAID "
clean_status = raw_status.strip().lower()
print(clean_status)                # paid
print(raw_status)                  # "  PAID " (unchanged)
print(clean_status == "paid")      # True
```

**How it works:** `strip()` removes surrounding whitespace; `lower()` returns lowercase text. Strings are **immutable**, so the cleaned result must be assigned to a name. **JS equivalent:** `rawStatus.trim().toLowerCase()`.

| Raw value | `strip()` | `lower()` |
|---|---|---|
| `" PAID "` | `"PAID"` | `"paid"` |
| `" Delivered  "` | `"Delivered"` | `"delivered"` |
| `"failed"` | `"failed"` | `"failed"` |

### Split, join and format

```python
line = "101,Pune,2500"
fields = line.split(",")
print(fields)                         # ['101', 'Pune', '2500']
print(int(fields[2]) + 500)           # 3000
print(" | ".join(fields[:2]))         # 101 | Pune
print(f"Total: ₹{int(fields[2]):,}") # Total: ₹2,500
```

- `split(",")` turns simple comma-separated text into a list; `join()` goes the other way.
- For real CSV with quoted commas, use `csv.DictReader`, not `split(",")`.
- `f"Total: ₹{value:,}"` is similar to JS template strings `${value}` with formatting options.
- `str.replace()`, `startswith()`, `endswith()` and `in` help normalize and validate records.

### Input and missing data traps

`input()` **always returns a string**, even if the user enters `42`. `int("42")` works, but `int("forty-two")` raises `ValueError`. A missing input should not silently become zero.

**Avoid `eval(input())`:** never execute arbitrary user-supplied text.

## 5. Input and output

```python
name = input("Name: ") # input() returns a str
print("Hello", name)
```

Convert input before numeric operations, e.g. `age = int(input("Age: "))`. Input can fail when text is not numeric; error handling comes later.

### Running your first script (p. 5)

Create a file named `hello.py` before executing it. On macOS/Linux, run `python3 hello.py`; on Windows with the Python launcher, use `py hello.py`. Check the interpreter with `python3 --version` or `py --version`. A virtual environment isolates project packages:

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 hello.py
```

On Windows, create the same environment with `py -m venv .venv`, then activate it using the command appropriate to your shell. Python is case-sensitive: `print()` works, while `Print()` raises `NameError`. A missing indented block after `if ...:` raises `IndentationError`. **JS comparison:** a `.py` file is a saved script like a `.js` file, but Python's significant indentation replaces JavaScript's braces.

### Assignment and naming essentials (p. 6)

```python
first, second = 10, 20
first, second = second, first
tax_rate = 0.18
order_total = 1000
order_total += 200
print(first, second, order_total)  # 20 10 1200
```

`a, b = b, a` swaps values using tuple unpacking. `x = y = 0` assigns both names. Uppercase `GST_RATE` is only a *convention* for constants, not enforcement. Names cannot begin with digits or use keywords like `class`. `Amount` and `amount` are distinct, and referencing a name before assignment raises `NameError`.

### String presentation and validation (p. 8)

```python
revenue, count = 4143.0, 3
print(f"{revenue:,.2f}")       # 4,143.00
print(f"{count:03d}")         # 003
print(f"{0.256:.1%}")         # 25.6%
print(" | ".join(["a", "b", "c"]))  # a | b | c
```

`f`-strings make reports readable. `,.2f` is a thousands separator and two decimal places; `03d` zero-pads integers; `.1%` formats a proportion. `text.count("a")` counts occurrences, `"orders.csv".endswith(".csv")` checks the suffix, and `"x" in text` checks membership. `"\\n"` and `"\\t"` represent newlines and tabs. For true CSV with quoted delimiters, use the `csv` module—not a plain split.

## Mentorship source audit: formatted output and interactive input (PDF p. 10; 2026-11-09)

Use `print(..., sep=" | ")` to control the separator and `print(..., end="...")` to control the line ending. An empty `print()` creates a blank line. This is useful for consistent logs, though a production ETL often writes structured logs.

```python
print("order", 101, "delivered", sep=" | ")  # order | 101 | delivered
print("loading", end="... ")
print("done")  # loading... done
```

`input()` returns text even when a user types a number. Converting a bad whole-number string such as `"3.5"` using `int()` raises `ValueError`; validate or handle expected errors instead of silently making it zero. Align receipts with format widths such as `f"{'qty':>4}"` for right alignment and `f"{'item':<16}"` for left alignment. **Runtime-verified terminal nuance (PDF p. 10, example 2):** An `input("Price per item: ")` prompt does **not** itself finish with a newline. The following bare `print()` moves the cursor to the next line, but does not create a second *empty* line as the archived displayed transcript implies. If a visibly blank line is required after that prompt, call `print("\n")` (or print two newlines deliberately). In a real terminal, typed characters may be echoed; redirected stdin is not. ## Archived foundations: exact money and timestamps (PDF p. 27; 2026-11-09)

Avoid binary floating-point for exact currency. Construct `Decimal` from **text**, not an already-rounded float, then choose the required rounding policy:

```python
from decimal import Decimal, ROUND_HALF_UP
amount = Decimal("2.675")
print(amount.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))  # 2.68
```

Python's `round(2.5)` uses ties-to-even (result `2`); business rounding requirements should be explicit. `len("café")` is 4 characters while its UTF-8 byte representation is 5 bytes. Text must be deliberately encoded/decoded.

**Naive timestamps** lack a time zone. Prefer `datetime` objects with an actual zone (`zoneinfo.ZoneInfo("Asia/Kolkata")`) and convert instants to UTC for storage/comparison:

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo
local = datetime(2025, 4, 1, 10, 0, tzinfo=ZoneInfo("Asia/Kolkata"))
print(local.astimezone(timezone.utc).isoformat())  # 2025-04-01T04:30:00+00:00
```

This local-zone example assumes the runtime has IANA timezone data installed. Don't attach a zone to a timestamp that actually represents a different time zone. Compare aware values consistently.

## Bosscoder Refresher-1 source cross-check: names, shared mutation, frozen sets (2026-11-10)

The archived [Lecture-01 type and scope notes](<../../99. Reference Materials/Legacy Journey Snapshot/02-python/bosscoder/lecture-01/01-basics-and-types.md>) distinguish **names** from the **objects** they reference. Rebinding a name is different from changing a shared mutable object:

```python
first = [1, 2]
alias = first          # both names reference one list
alias.append(3)        # modifies the shared list
print(first)           # [1, 2, 3]
alias = [9]            # rebinds alias; first still refers to [1, 2, 3]
print(first)           # [1, 2, 3]
```

`set` stores unique hashable values without a guaranteed traversal order; `frozenset` is its **immutable** counterpart, and can be a dictionary key if all its elements are hashable. Local names normally belong to a function; use parameters and return values instead of rebinding a module-level name with `global` whenever practical. `del variable` removes a name binding, not necessarily the underlying object if other references remain.
