# Operators and Decisions — Foundation Notes

**Main idea:** Operators calculate and compare values; `if` chooses what code runs.

## 1. Arithmetic

```python
print(17 / 5)   # 3.4 (division)
print(17 // 5)  # 3   (floor division)
print(17 % 5)   # 2   (remainder)
print(2 ** 3)   # 8   (power)
```

`//` rounds **toward negative infinity**, not toward zero:

```python
print(-13 // 4) # -4
print(-13 % 4)  # 3
```

Remember: `a == (a // b) * b + (a % b)`. With positive `b`, the remainder is nonnegative. **Revision priority:** negative modulo.

## 2. Comparisons and logic

```python
amount = 1000
status = "SUCCESS"
print(amount >= 1000)                   # True
print(amount == "1000")                 # False: int != str
print(amount > 0 and status == "SUCCESS") # True
print(not (amount < 0))                 # True
```

| JavaScript | Python |
|---|---|
| `===` (strict-value comparison) | `==` (equality; with Python type rules) |
| `&&` | `and` |
| `||` | `or` |
| `!` | `not` |

Python `True` and `False` are capitalized. Unlike JavaScript, `10 == "10"` is false.

## 3. Conditions

```python
amount = 750
status = "SUCCESS"

if status != "SUCCESS":
    print("Failed")
elif amount >= 1000:
    print("High value")
else:
    print("Regular")       # output
```

**How:** Python checks branches top-to-bottom and executes only the first matching branch. `:` starts a block; indentation (usually four spaces) defines its body.

**JavaScript link:** Python `elif` is JavaScript `else if`; Python indentation replaces `{ ... }`.

## Quick revision

- `>` excludes equality; `>=` includes equality.
- `=` is assignment; `==` is comparison.
- `if`, `elif`, `else` must be aligned, each ending in `:`.
- A `print()` outside the indented block runs after the conditional.

## Mentorship source audit: comparisons, truthiness and decision order (PDF pp. 9, 11; 2026-11-09)

Python supports **chained comparisons**: `500 < amount < 2000` is equivalent to two comparisons joined with `and`. `x in collection` checks membership. Use `value is None` rather than `value == None` to check for missing values.

A condition can use truthiness: `0`, `""`, empty lists/dictionaries and `None` are false; a nonempty text value such as `"False"` is **true**. This matters when validating imported CSV strings—never assume `bool("False")` means false.

**Ordering matters** when classifying records. Check `amount >= 2000` before `amount >= 1000`, or a 2500 order will be labeled medium and never reach the large branch. A concise `label = "high" if amount >= 2000 else "normal"` works for simple two-way decisions; prefer a full `if/elif/else` when there are multiple rules.

Python 3.10+ also supports pattern matching:

```python
status = "returned"
match status:
    case "cancelled" | "returned":
        label = "excluded"
    case "delivered":
        label = "counted"
    case _:
        label = "unknown"
print(label)  # excluded
```

**Boundary test:** `amount=1000` must enter the medium bracket and `amount=2000` must enter the large bracket. **Audit scope:** mentorship lesson text cross-checked; independently completing its exercises and official W3Schools comparison remain separate.


## Mentorship error-handling review (PDF p. 21; 2026-11-09)

Read Python's traceback **from the bottom** for the final exception type/message, then inspect the source line and caller context. Common cases include `NameError`, `TypeError`, `ValueError`, `IndexError`, `KeyError`, `ZeroDivisionError` and `FileNotFoundError`. Catch a **specific expected error**, not every exception. For empty input, `sum(values)/len(values)` raises `ZeroDivisionError`; choose deliberately between returning `None`, returning zero, or raising a documented exception because zero can conceal missing data.

```python
def average_or_none(values):
    return sum(values) / len(values) if values else None
print(average_or_none([]))          # None
print(average_or_none([1198, 796])) # 997.0
```

For bad numeric rows, append rejected values to a separate list for diagnosis. `assert` is useful as a development check but must not replace production input validation because assertions can be disabled with Python optimization. **Audit scope:** mentorship p. 21 reviewed; no learner exercise completion claimed.

## Bosscoder Refresher-1 source cross-check: bitwise versus logical operators (2026-11-10)

The archived [Lecture-01 operator notes](<../../99. Reference Materials/Legacy Journey Snapshot/02-python/bosscoder/lecture-01/02-operators-and-slicing.md>) cover a genuinely separate concept: **bitwise** operators manipulate integer bits, while `and`/`or` evaluate truthiness and return operands. For example, `6` is binary `110` and `3` is `011`:

```python
print(6 & 3)   # 2, bitwise AND: 010
print(6 | 3)   # 7, bitwise OR: 111
print(6 ^ 3)   # 5, XOR: 101
print(~6)      # -7, since ~n = -n - 1
print(6 << 1)  # 12, shift left
print(6 >> 1)  # 3, shift right
```

**Do not confuse** `6 & 3` (integer `2`) with `6 and 3` (the original integer operand `3`). For membership, `key in some_dict` tests **keys**, not values. For identity, `a is b` asks whether two names reference the same object; use `==` for value equality and `is None` for missing-value sentinel checks.
