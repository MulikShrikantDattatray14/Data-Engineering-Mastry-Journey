# Functions and Reuse — Foundation Notes

## Why learn this?

Imagine 10,000 orders need the same discount calculation. Repeating the code in multiple places risks inconsistent logic. A **function** lets you define a reusable transformation once and call it wherever needed.

## 1. Define and call

```python
def add_tax(amount, rate=0.10):
    return round(amount * (1 + rate), 2)

print(add_tax(100))       # 110.0
print(add_tax(100, 0.20)) # 120.0
```

- `def` starts the function.
- `amount` and `rate` are **parameters**; `100` is an **argument**.
- `rate=0.10` supplies a default.
- `return` gives a value back to the caller.

**JavaScript comparison**

```javascript
function addTax(amount, rate = 0.10) {
  return Number((amount * (1 + rate)).toFixed(2));
}
```

## 2. Printing is not returning

```python
def display_total(a, b):
    print(a + b)

result = display_total(2, 3) # prints 5
print(result)                # None
```

The function **displayed** 5 but didn't return it. A function without `return` returns `None`.

## 3. Split a pipeline into testable steps

```python
def is_valid(amount):
    return amount > 0

def clean_sales(rows):
    cleaned = []
    for amount in rows:
        if is_valid(amount):
            cleaned.append(amount)
    return cleaned

print(clean_sales([100, -5, 200])) # [100, 200]
```

**Data flow:** raw values → `is_valid()` → keep positives → `clean_sales()` returns new list. One job per function makes tests and debugging simpler.

## 4. Local scope

```python
def double(n):
    output = n * 2
    return output

print(double(10)) # 20
# print(output) would raise NameError
```

A local variable belongs to its function. Unlike JavaScript's `let` in a block, Python `if` blocks do **not** introduce a new function-local scope.

## 5. Important caution — mutable defaults

Avoid `def add(value, items=[]):` because the same default list is reused between calls. Prefer:

```python
def add(value, items=None):
    if items is None:
        items = []
    items.append(value)
    return items
```

## Quick revision

- `return` makes a function's result reusable; `print` merely displays.
- Functions are values: they can be stored, passed and returned.
- `lambda` is a short expression-based function, useful for simple keys but not a substitute for readable multi-step logic.
- Test functions on empty lists, invalid inputs and boundaries.

## Mentorship audit: arguments, functional keys and robust mini-pipelines (PDF pp. 18–19; 2026-11-09)

Use a **docstring** immediately under `def` to document behavior. Positional arguments fill parameters in order; keyword arguments like `add_tax(rate=0.12, amount=500)` use names. Functions can also be passed as values, for example `sorted(products, key=lambda item: item[1])` to sort `(name, price)` records by price, not name.

A lightweight pipeline can apply an ordered sequence of transformations:

```python
def trim(s): return s.strip()
def normalize(s): return s.lower()
status = "  DELIVERED  "
for step in [trim, normalize]:
    status = step(status)
print(status)  # delivered
```

**Source edge-case correction:** an archived introductory mini-pipeline checks field count before using `int(order_id)` and `float(amount)`, but a row with *three fields and bad numeric text* can still raise `ValueError`. At the production boundary, catch conversion errors explicitly and report rejected records instead of assuming every row parses:

```python
def parse_order(line):
    parts = line.split(",")
    if len(parts) != 3:
        return None
    try:
        return {
            "id": int(parts[0]),
            "status": parts[1].strip().lower(),
            "amount": float(parts[2]),
        }
    except ValueError:
        return None  # caller should log/record rejection
```
