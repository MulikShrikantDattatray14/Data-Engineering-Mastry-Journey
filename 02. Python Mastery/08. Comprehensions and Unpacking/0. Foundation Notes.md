# Comprehensions and Unpacking — Foundation Notes

## Why do we need this?

Data pipelines transform collections: keep successful orders, extract amounts, build lookup dictionaries and unpack paired fields. Python **comprehensions** express common *filter-and-transform* operations concisely.

You already know JavaScript's `filter()` and `map()`. Python can combine them in one readable expression.

## 1. Visualizing the same work

| Record | Status | Amount | Action |
|---:|---|---:|---|
| 101 | delivered | 120 | Keep 120 |
| 102 | cancelled | 900 | Skip |
| 103 | delivered | 80 | Keep 80 |

```python
orders = [
    {"id":101,"status":"delivered","amount":120},
    {"id":102,"status":"cancelled","amount":900},
    {"id":103,"status":"delivered","amount":80},
]
amounts = [row["amount"] for row in orders if row["status"] == "delivered"]
print(amounts) # [120,80]
```

Read it: **output expression** `row["amount"]` → **for each row** → **only if delivered**.

### JavaScript equivalent

```javascript
const amounts = orders
  .filter(row => row.status === "delivered")
  .map(row => row.amount);
```

## 2. List, set and dictionary comprehensions

```python
statuses = {row["status"] for row in orders}
by_id = {row["id"]: row["amount"] for row in orders}
print(sorted(statuses)) # ['cancelled', 'delivered']
print(by_id[103])       # 80
```

- `[expression for ...]` makes a list.
- `{expression for ...}` makes a set, removing duplicates.
- `{key: value for ...}` makes a dictionary, with unique keys.

## 3. Unpacking, enumerate and zip

```python
for index, city in enumerate(["Pune","Mumbai"], start=1):
    print(index, city)
# 1 Pune
# 2 Mumbai

pairs = list(zip([101,102], ["paid","failed"]))
print(pairs) # [(101,'paid'),(102,'failed')]
```

`enumerate()` attaches positions. `zip()` pairs items and normally stops at the shortest input; in Python 3.10+ use `zip(a,b, strict=True)` to detect mismatched lengths.

## When NOT to use a comprehension

If a transformation needs complex branching, logging, validation or multiple steps, use a **normal `for` loop**. Readability beats clever one-liners.

## Revision

- A generator expression uses parentheses, `(expr for ...)`, and is lazy.
- Don't accidentally overwrite a dictionary's value when duplicate keys appear.
- Use `list(zip(...))` when you actually need to materialize all pairs.
- Avoid doing database writes or other side effects inside comprehensions.

## Archived foundations: unpacking and strict pairing (PDF p. 30; 2026-11-09)

```python
ids = [101, 102]
amounts = [1198, 796]
print(dict(zip(ids, amounts, strict=True)))  # {101: 1198, 102: 796}
head, *middle, tail = [10, 20, 30, 40]
print(head, middle, tail)                    # 10 [20, 30] 40
```

`zip(..., strict=True)` (Python 3.10+) raises `ValueError` when inputs have unequal lengths, preventing silent source-to-target column truncation. A generator expression such as `sum(r["amount"] for r in rows)` avoids building an extra intermediate list. `any()` and `all()` stop once an answer is determined. Use ordinary loops when validation and logging matter more than terseness.
