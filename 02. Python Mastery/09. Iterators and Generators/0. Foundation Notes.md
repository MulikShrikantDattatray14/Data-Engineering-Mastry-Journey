# Iterators and Generators — Foundation Notes

## Why do we need this?

Suppose a transaction file contains **ten million rows**. Creating a list of all records can consume unnecessary memory. A generator can **produce the next row only when needed**.

## The mental picture

```text
A list:       [100, 200, 300, 400]  → all values exist in memory
A generator:  ask → 100
              ask → 200
              ask → 300
              ask → 400
              ask → StopIteration
```

## 1. A small generator

```python
def positive_amounts(values):
    for value in values:
        if value > 0:
            yield value

pipeline = positive_amounts([100,-5,200])
print(next(pipeline)) # 100
print(next(pipeline)) # 200
print(list(pipeline)) # []  (already consumed)
```

`yield` pauses the function and remembers its position. `next()` resumes until it yields again. Once consumed, that iterator cannot automatically restart.

## 2. Data Engineering pipeline

```python
def delivered_amounts(rows):
    for status, amount in rows:
        if status == "delivered":
            yield amount

rows = [("delivered",100),("cancelled",500),("delivered",200)]
print(sum(delivered_amounts(rows))) # 300
```

The downstream `sum()` requests values from upstream; we do not build a second list.

## 3. JavaScript comparison

| JavaScript | Python |
|---|---|
| `function* gen() { yield 1; }` | `def gen(): yield 1` |
| `iterator.next()` | `next(iterator)` |
| `for (const x of iterable)` | `for x in iterable:` |
| `[...iterable]` | `list(iterable)` |

**Important distinction:** JavaScript async generators and Python async generators are separate advanced topics. Regular Python generators do **not** make blocking file reads asynchronous.

## Common traps

- Creating a generator doesn't run its body until iteration begins.
- A generator is typically **single-pass**.
- `list(generator)` eagerly consumes it and uses memory.
- If you need to reread a file, recreate the generator from the source.
- A generator can still perform side effects; avoid hidden mutations and log exceptions carefully.
