# Pandas for Data Engineering — Foundation Notes

## Why do we need this?

SQL transforms tables in a database; **pandas** helps manipulate tabular files and in-memory datasets in Python. Understanding the same operation in both languages makes an experienced JavaScript developer transition faster.

## 1. Tiny order dataset

| order_id | status | amount |
|---:|---|---:|
| 101 | delivered | 100 |
| 102 | cancelled | 500 |
| 103 | delivered | 200 |

Our business question: **total delivered revenue**.

## 2. SQL versus pandas

**SQL**

```sql
SELECT SUM(amount) AS revenue
FROM Orders
WHERE status='delivered';
```

**Pandas**

```python
import pandas as pd
df = pd.DataFrame([
    {"order_id":101,"status":"delivered","amount":100},
    {"order_id":102,"status":"cancelled","amount":500},
    {"order_id":103,"status":"delivered","amount":200},
])
delivered = df.loc[df["status"] == "delivered"]
print(delivered["amount"].sum()) # 300
```

## 3. Watch the rows change

```text
RAW (3 rows)                         FILTERED (2 rows)
101 delivered 100       ───────→     101 delivered 100
102 cancelled 500       [removed]    103 delivered 200
103 delivered 200                    ────────────────
                                     SUM = 300
```

## 4. Important pandas concepts

| Goal | Pandas approach |
|---|---|
| Load CSV | `pd.read_csv(path)` |
| Inspect rows | `df.head()`, `df.shape` |
| Filter rows | `df.loc[condition]` |
| Select columns | `df[["a","b"]]` |
| Group/aggregate | `df.groupby("status")["amount"].sum()` |
| Join datasets | `df.merge(other, on="id", how="left")` |
| Handle null | `df.isna()` and careful `fillna()` |

## 5. Dangerous mistakes

- Missing values aren't automatically zero. Filling NULL with zero changes some business metrics.
- `merge()` with duplicate keys can **multiply rows**, just like SQL joins.
- Pandas is **in-memory** for many operations; a CSV larger than memory may require chunked streaming, Spark or a database.
- Date strings should be parsed into date types before extracting months.
- Avoid slow row-by-row Python loops when vectorized pandas operations can do the work efficiently.

**JavaScript analogy:** A DataFrame is not merely `Array<Object>`; pandas provides typed column operations, vectorization and index alignment, with different missing-value semantics.

## Archived source review: pandas pitfalls, ranking and Spark transition (PDF pp. 69–70, 74; 2026-11-09)

**A SQL-to-pandas mental map:** `WHERE` → `.loc[condition]`, `GROUP BY` → `.groupby(...).agg(...)`, `JOIN` → `.merge(...)`, `DENSE_RANK` → `.groupby(key)[value].rank(method="dense")`. Parse date columns before `.dt.to_period("M")`; otherwise `.dt` is not available.

**Four high-impact correctness traps:**

1. **Null groups vanish by default.** `df.groupby("city")` normally excludes missing-city groups. Use `dropna=False` where those rows belong in the metric, and reconcile totals against the input.
2. **Chained assignment is unreliable.** Prefer `df.loc[mask, "amount"] = 0` over `df[mask]["amount"] = 0`.
3. **Duplicate lookup keys multiply rows.** `df.merge(customers, on="customer_id", validate="many_to_one")` fails deliberately if the right side is unexpectedly nonunique.
4. **Row iteration is slow and error-prone.** Prefer vectorized column operations and explicit dtypes. Conversion and null handling may still change semantics.

A groupwise `idxmax()` chooses **one** maximum row; `rank(method="dense").eq(1)` retains all tied maxima. `merge` defaults and join-cardinality rules matter as much as in SQL.

**When to use Spark:** pandas is useful for manageable in-memory work and local tests; PySpark plans distributed transformations, with actions such as `.show()` triggering execution. A SQL analytic window can be expressed using `Window.partitionBy(...).orderBy(...)`. Airflow defines *dependencies, scheduling and retries*, not how each transformation's business logic is calculated. The archived source's Airflow example is illustrative and **was not independently executed** in this audit.

## Source-checked pandas caveats (mentorship pp.69–70; 2026-11-10)

**Reconcile the measure, not just the shape.** The source's monthly summary sums **order-header** `orders.amount`, while the category pivot recomputes revenue from `order_items.qty * unit_price`. Those are separate grains and can disagree if discounts, returns, taxes, rounding or missing/mismatched line items exist. Confirm the business definition before combining these reports. The original p.69 source publishes pandas dtype labels `datetime64[us]` and `str`; displayed dtypes and some warnings vary across pandas versions, so inspect actual `df.dtypes` rather than assuming the screenshot text is universal.
