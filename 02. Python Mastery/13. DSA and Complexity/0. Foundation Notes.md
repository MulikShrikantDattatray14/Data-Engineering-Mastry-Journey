## 1. Time, space and trade-offs (pp. 41–44)

| Pattern | Typical time | DE interpretation |
|---|---|---|
| Known index lookup | O(1) | Read one known array element |
| Binary search on sorted keys | O(log n) | Locate a partition boundary |
| Single pass | O(n) | Validate every input record |
| Sorting | O(n log n) | Order events by timestamp |
| Nested all-pairs comparison | O(n²) | Expensive duplicate detection |

Big-O describes **growth**, not precise runtime seconds. A recursive call stack counts toward extra memory. `sum(x * 2 for x in values)` generates values without storing an additional doubled list; `[x * 2 for x in values]` creates a separate list of size O(n).

Use a `set` when checking many repeated ID memberships, not `if id in list:` inside another long loop. A set costs O(n) build time and space but gives average O(1) lookups. `collections.deque.popleft()` is O(1) whereas removing from the front of a Python list shifts items and is O(n). Prefix sums trade O(n) stored cumulative values for O(1) range-sum queries after preprocessing.

## 2. Two pointers, hashing, windows (pp. 45–47)

**Two pointers:** on a *sorted* list, start at both ends. If the pair sum is too small, advance the left pointer; if too large, retreat the right. This avoids checking every pair.

```python
def pair_sum(sorted_values, target):
    left, right = 0, len(sorted_values) - 1
    while left < right:
        total = sorted_values[left] + sorted_values[right]
        if total == target:
            return (sorted_values[left], sorted_values[right])
        if total < target:
            left += 1
        else:
            right -= 1
    return None

print(pair_sum([2, 5, 7, 11], 13))  # (2, 11)
```

**Hashing:** for *unsorted* two-sum, remember previous values in a dictionary and look up each `target - current`; this usually costs O(n) time and O(n) extra space. Prefix-sum hash tables also count contiguous ranges with a target total.

**Sliding windows:** the variable-sized window maintains a left and right boundary. Longest substring without repeats uses a dictionary of last-seen character indexes. A shortest positive-sum window can shrink whenever the running total reaches the target; that simple monotonic technique is **not generally valid with negative amounts**. A rolling event window should compare real timestamps, not string fragments.

## 3. Stacks, queues, linked lists (pp. 48–49)

A **stack** is last-in-first-out; it can match nested brackets or find the next greater value with a monotonic stack. A **queue** is first-in-first-out; use `collections.deque` for breadth-first processing.

A linked-list node stores a value and a `next` reference. Reversing a list needs three references (`previous`, `current`, `following`), carefully saving `following` before rewiring the link. Floyd's slow/fast pointers detect cycles without storing all nodes. Python's built-in `list` is a dynamic array, not a linked list.

## 4. Binary search and sorting (pp. 50–51)

Binary search requires a **monotonic predicate**. For a sorted array, the lower bound is the first index whose value is at least the target; it can equal `len(values)` when there is no match. `bisect_left(values, target)` is the standard-library implementation.

```python
from bisect import bisect_left
days = ["2025-01-10", "2025-02-02", "2025-03-05"]
print(bisect_left(days, "2025-02-01"))  # 1
```

Binary search on an **answer** works if increasing the candidate causes feasibility to change only once. Merge sort takes O(n log n) time and O(n) extra space. Python's sort is stable and is preferred in ordinary ETL code; counting sort needs a manageable bounded key range.

## 5. Recursion, trees and pipeline DAGs (pp. 52–54)

A recursive function needs a base case and smaller subproblems. Backtracking selects, explores, undoes, and tries alternatives; prune branches known to be impossible. Recursion depth and call-stack memory matter for deeply nested JSON.

**DFS** explores a branch deeply; **BFS** visits breadth-wise and uses a queue. They help traverse employee reporting trees, folder structures, and event dependencies.

A directed acyclic graph (DAG) models ETL tasks and prerequisites. **Topological sorting** repeatedly schedules zero-indegree tasks and decrements its dependents; if some nodes remain unscheduled, a cycle is present.

```python
from collections import defaultdict, deque
def topo(tasks, edges):
    children = defaultdict(list)
    degree = {task: 0 for task in tasks}
    for before, after in edges:
        children[before].append(after)
        degree[after] += 1
    ready = deque(task for task in tasks if degree[task] == 0)
    output = []
    while ready:
        task = ready.popleft()
        output.append(task)
        for nxt in children[task]:
            degree[nxt] -= 1
            if degree[nxt] == 0:
                ready.append(nxt)
    if len(output) != len(degree):
        raise ValueError("cycle detected")
    return output

print(topo(["extract", "clean", "load"], [("extract", "clean"), ("clean", "load")]))
# ['extract', 'clean', 'load']
```

For production DAGs, also handle unknown dependency IDs and task failures; this simplified teaching function assumes all edge endpoints are listed in `tasks`.

## 6. Heaps, greedy and DP (pp. 55–56)

A min-heap exposes its smallest element. `heapq.heappush` and `heappop` cost O(log n) and are useful for the next earliest checkout, top-K values, and streaming medians (often with two heaps). Greedy interval selection picks the interval finishing earliest when maximizing non-overlapping intervals; greedy is correct only when justified by the problem's structure.

Dynamic programming caches overlapping subproblems. Fibonacci illustrates memoization; a recurrence with only the last two states can use O(1) extra space. Coin change builds answers for smaller amounts; Kadane's algorithm keeps the best subarray sum ending at the current position. Define the **state, transition, base case and answer** before coding.

## Source-verified pitfalls from original mentorship DSA pages 41–46

The preserved [page-by-page code/output audit](../../MENTORSHIP-PAGES-41-46-RUNTIME-AUDIT.md) records exact source links and uses source-extracted examples; synthetic reviewer tests are explicitly separate from official solutions and student work.

- **A dictionary-based two-sum returns *positions* rather than the price values** in the page-46 exercise. Look for a complement **before** inserting the current element so `[5]` never counts as two distinct records for a target of 10; `[5, 5]` is a valid two-record pair.
- **Prefix-count subarrays require an empty-prefix occurrence.** Start with `Counter({0: 1})` *before* scanning the data, then add matches before incrementing the current prefix count. In `[-1, 1, 0]`, three nonempty ranges sum to zero: `[-1,1]`, `[-1,1,0]`, `[0]`. A simple positive-only sliding window would miss cases involving negative values.
- **Sorted deduplication changes its input list.** The page-45 `dedupe_sorted` both returns the unique length and removes the stale suffix with `del ids[write:]`; the pointer scan is O(n) only when input is already sorted.
- **Memory experiments prove only what they print.** Page 42's `tracemalloc` demonstration prints the stable comparison `list uses more peak memory: True`, not fixed KB values. Generator values can be exhausted; recursive function calls consume stack space.
