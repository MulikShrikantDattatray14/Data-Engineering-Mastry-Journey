## 2. Explain a question using the six-step approach

1. Repeat the exact input/output contract and define expected ordering.
2. Ask about `None`, missing keys, duplicates, ties, dates and invalid amounts.
3. Give a simple correct algorithm and a hand-worked tiny fixture.
4. Improve it with the right data structure and avoid hidden quadratic scans.
5. Write testable extraction, normalization and aggregation stages.
6. State time/space complexity and test failure and boundary cases.

Example: a *top customer per month* requires filtering delivered orders, deriving calendar month, summing by (month, customer), then selecting the maximum. With pandas, `idxmax()` chooses one winner while `rank(method="dense")` can retain all ties. You must state the intended rule.

## 4. Complexity quick checks (PDF p. 78)

| Tool | Cost to explain |
|---|---|
| List index / append | O(1) typical / amortized append |
| List membership | O(n) |
| Dictionary or set lookup | O(1) average; collision caveats |
| `deque.popleft()` | O(1) |
| Heap push/pop | O(log n) |
| `bisect_left` on sorted list | O(log n) search position; O(n) insert shift |
| Iterative binary search | O(log n) time / O(1) extra space |
| BFS/DFS on graph | O(V+E), plus visited/queue or stack memory |
| Sort | O(n log n), and implementation-dependent extra memory |

Explain **why** the loop/structure has that complexity; do not memorize big-O labels without identifying the actual repeated work.
