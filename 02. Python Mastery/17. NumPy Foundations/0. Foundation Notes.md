## 1. NumPy arrays versus Python lists

A Python list can store mixed Python objects, while a typical `numpy.ndarray` has one dtype and supports elementwise numerical operations. Vectorization often avoids Python-level loops.

```python
import numpy as np
amounts = np.array([1198.0, 796.0, 1499.0])
print(amounts.shape, amounts.ndim, amounts.dtype)
print((amounts * 2).tolist())
# (3,) 1 float64
# [2396.0, 1592.0, 2998.0]
```

`shape` is the length of each dimension, `ndim` counts dimensions, `size` counts elements, and `dtype` describes element storage. Array creation includes `np.array`, `zeros`, `ones`, `arange`, `linspace`, `eye` and methods to set shapes. Unlike `range`, `np.arange` produces an actual array.

## 2. Shapes, reshape, flatten and views

```python
grid = np.arange(6).reshape(2, 3)
print(grid.shape)  # (2, 3)
print(grid[:, 1].tolist())  # [1, 4] second column
print(grid.T.shape)  # (3, 2)
```

`reshape` changes the shape if the element count remains consistent; one dimension may be `-1` for inference. `flatten()` always returns a copy, whereas `ravel()` may return a **view** sharing storage. Modifying a view can change the original array; verify `np.shares_memory(a,b)` when this matters.

A basic slice generally creates a view; **advanced/fancy or boolean indexing** generally creates a copy. Confusing these can silently lose edits to a filtered array. Pandas has related but distinct copy/view behavior.

## 3. Boolean masks, broadcasting and computing

```python
values = np.array([100, -20, 300, 0])
positive = values > 0
print(positive.tolist())  # [True, False, True, False]
print(values[positive].tolist())  # [100, 300]
```

Broadcasting combines different shapes when their **trailing dimensions are compatible** (equal or one of them is 1). E.g. a 2×3 matrix plus a length-3 row vector broadcasts across both rows. This is not simply a requirement that the shapes be identical.

`np.mean`, `np.min`, `np.max`, `np.std`, `np.sum` reduce values; the `axis` controls which dimension is reduced. Compare population standard deviation defaults with sample formulas before interpreting results. Division by zero on floating arrays often issues a warning and yields `inf` or `nan`, rather than the ordinary scalar `ZeroDivisionError`.

**Source correction:** `np.add(a, b, out)` treats the third positional argument as an **output array**, not an unused third operand. It may modify `out`; always understand `out=` before calling ufuncs.

## 4. Manipulations and linear algebra

- `np.concatenate` joins arrays along an **existing axis**; `np.stack` creates a **new axis**.
- `np.expand_dims` inserts a size-1 axis; `np.squeeze` removes size-1 dimensions.
- `np.split` divides an array subject to specified boundaries; `.T` transposes axes for a 2D array.
- `@ ` and `np.matmul` perform matrix multiplication, not elementwise `*`. Matrix shape rules are different from elementwise broadcasting.
- Numerical transforms include `np.sin`, `np.cos`, and `np.linalg.det`; explain dimensional requirements before using these.

## 5. Structured arrays with named fields

For compact fixed-schema records, a structured array can store named fields with explicit dtypes:

```python
import numpy as np
rows = np.array([(101, 1198.0), (102, 796.0)],
                dtype=[("order_id", "i4"), ("amount", "f8")])
print(rows["order_id"].tolist())  # [101, 102]
print(np.sort(rows, order="amount")["order_id"].tolist())  # [102, 101]
```

Structured arrays are not a drop-in replacement for a relational table or pandas DataFrame. They are useful when array storage and fixed field definitions matter.

## When to prefer NumPy vs pandas vs Spark

Choose NumPy for numerical arrays and matrix calculations; pandas for labeled columns, joins and tabular analysis that fit in memory; Spark when distributed partitioning, shuffle behavior and fault tolerance justify the added complexity. Profile real workloads instead of assuming vectorization is always fastest.
